- Keep season reference data and validation in a shared browser-safe module; AI explanations live in a server function with server-only gateway helpers so credentials never enter the browser.
- Season assistance is a single form-driven explanation without conversation history; deterministic reference guidance remains available when AI is unavailable.
- The season guide holds no measurements, so a season explanation that states a figure was invented and is replaced by the deterministic reference summary.
- The farmer Q&A assistant keeps a conversation thread in the page but sends only the most recent turns to the server; keep its contract, suggested prompts, and copy in a shared browser-safe module.
- All AI runs against an OpenAI-compatible backend configured by `AI_API_KEY`, `AI_BASE_URL`, and `AI_MODEL`; never hardcode a provider, gateway, or credential, and keep the deterministic guidance visible when AI is unavailable.
- The speech backend is an OpenAI-compatible endpoint configured by `AI_SPEECH_BASE_URL` and the shared credential, behind the server-side gateway and never in the browser.
- The speech request carries only the standard OpenAI speech fields, because a strict endpoint rejects anything else with `unknown field`; the language is chosen by the voice the model is asked for.
- The server reports which app languages the speech backend can speak aloud, and a language it cannot read is offered as writing only rather than spoken badly. The server refuses a language it cannot speak instead of returning audio in the wrong one.
- A speech backend that cannot serve requests, for example one whose plan or terms do not cover it, is not shown as an error: the answer stays written and the page stays calm.
- A backend that cannot read aloud at all is remembered for the visit: the panel says so calmly and stops offering a spoken button, and the refusal reason is reported to whoever runs the deployment.
- The voice panel shows only the problems a farmer can act on, such as a blocked microphone or a language the backend cannot read aloud. A request that simply fails is left unanswered rather than shown as an error.
- Keep farmer translations in a shared browser-safe catalog and pass a validated language code to season explanations, so UI and AI advice use the same language without changing model selection.
- Automatic crop requests are debounced and discard superseded responses; preserve entered weather values and do not fabricate district climate data.
- Keep district land-use parsing and share calculations browser-safe and separate from crop training; imports are session-local aggregates so survey observations are not confused with physical land allocations.
- Render deployment uses the root Blueprint and the backend Docker context; verify model-dependent endpoints before considering a healthy service prediction-ready.
- Bundle openly licensed district boundaries with attribution; missing district measurements stay unavailable rather than being inferred from national totals.
- Keep insurance guidance in a browser-safe multilingual catalog; district and soil provide field context, never fabricated risk scores, eligibility, premiums or insurer rankings. Link official program information and require policy confirmation.
- Verify the free local AI stack through the app's own server functions with `scripts/test-app-ai-e2e.mjs`, not only through the raw OpenAI-compatible endpoints.
- Check the farmer's recorded question through the app's server functions even when the speech backend cannot read answers aloud, so a deployment proves the whole spoken path; the committed sample in `scripts/fixtures` keeps that check repeatable.
- Keep insurance coverage preferences separate from policy enrolment; stable coverage IDs preserve session choices across language changes without implying purchase or availability.
- Use the shared native-input Checkbox for coverage selection, avoiding a separate provider dependency while retaining accessible form behavior.
- Build every farmer-facing block as a labelled panel from the shared primitives in `src/components/ui`, and keep the design system in `src/styles.css` layered as tokens, components and layout; a status colour or surface never comes from an ad-hoc utility in a component.
- The NISR survey microdata, the training table and the trained models stay out of the repository; the models are fitted from the district, the season and the weather, because the survey records no soil type.
- A district's rain and temperature come from published records, never from an estimate made in the app, and a figure the farmer typed is never overwritten by a fetched one.
- A server function call must work on the deployment without any optional service configured: an unavailable service leaves the answer as it is, and never stops the call from being made.
- The agronomist assistant answers from a digest of the figures the dashboard shows, built on the server from the published survey figures, the model report and the district's climate; the model is told to quote no other number and to name a figure that is missing.
- A written plan may only quote figures its digest holds: an application rate, a spacing or a price the model adds is dropped before the farmer sees it.
- The Guidance portal is the help desk: every assistant is reachable from it in plain words, and the district and soil chosen there are the ones the assistants answer for.
